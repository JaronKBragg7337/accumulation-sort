The Accumulation Sort

Every repo on the account, run against one question — not whether it's good, but whether it's the thing you actually want.

  • Kind is what a repo is: a system, a theory, a book, a game or world, a tool, a life record, or a test. Repos are grouped by kind below.
  • Stage is how far it got: idea, designed (not built yet), partial, runs, accumulates. Furthest first.
  • Tier A–E is the founding question, kept as a second badge on every card.

The criterion. A system qualifies if it (1) runs without you, (2) is changed by having run, and (3) that change is legible when you come back. Continuation plus memory plus consequence. A screensaver passes the first test and fails the other two.

The founding question: tiers A–E

The tier badge on every card answers the question this page began with. It is a second reading of the same repo, not a second list.

    One idea, returned to six times. Persistent Memory Substrate → Atomic Chronicle → Keava Owent → Zeus → PAM Continuum. These are not failed attempts. Each one stops either because the principle had been extracted or because it hit a wall — and the next project, apparently unrelated, turns out to supply the layer that wall needed. The account is a record of layer extraction, not of abandonment.

    Nothing in the places and tools is wasted — it is the render layer that line never had. And in two repos the two halves have already met: the-current ticks its civilization server-side and archives its own eras, and livi-organism keeps revisioned cloud memory. Those are substrates wearing a world.

    The narrow version: one accumulating substrate, one world drawn on top of it, one live external constraint feeding it. Two of the three are already joined and running. What is missing is the third — nothing here is fed by anything outside itself.

    How this is sorted. Judgments (kind, stage, tier, principle, README drift) live in tiers.json and are applied to whatever the API returns today. They come from a full code read of every repo on 2026-10-14 plus an independent second read; where the two readers disagreed, the one that cited code or commits is used and the other is quoted on the card as “second reader”. Each row carries how far verification went: live system checked means the running database or deployment was inspected, source read means the code was, README read means only the README was, and metadata only means description and size alone.

    A README is a claim, not evidence. Descriptions here lag their code badly and in both directions — repos that describe a working system and contain a specification, and repos whose entire description is one word sitting on top of real implementation. so no judgment rests on a README alone. Where a README and the code disagree, the card says so under “README drift”.

    Repos created since the last edit to tiers.json appear under Not yet judged rather than being guessed at. Private repos are invisible to the API and are not counted.
