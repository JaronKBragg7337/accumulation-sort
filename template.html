The Accumulation Sort

Every repo on the account, run against one question — not whether it's good, but whether it's the thing you actually want.

The criterion. A system qualifies if it (1) runs without you, (2) is changed by having run, and (3) that change is legible when you come back. Continuation plus memory plus consequence. A screensaver passes the first test and fails the other two.

One idea, returned to six times. Persistent Memory Substrate → Atomic Chronicle → Keava Owent → Zeus → PAM Continuum. These are not failed attempts. Each one stops either because the principle had been extracted or because it hit a wall — and the next project, apparently unrelated, turns out to supply the layer that wall needed. The account is a record of layer extraction, not of abandonment.

Nothing in the Place tier is wasted — it is the render layer that line never had. And in two repos the two halves have already met: the-current ticks its civilization server-side and archives its own eras, and livi-organism keeps revisioned cloud memory. Those are substrates wearing a world.

The narrow version: one accumulating substrate, one world drawn on top of it, one live external constraint feeding it. Two of the three are already joined and running. What is missing is the third — nothing here is fed by anything outside itself.

How this is sorted. Tier judgments live in tiers.json and are applied to whatever the API returns today. Each row carries how far verification went: source read means the file tree or source was inspected, README read means the README was, metadata only means description and size alone — those are the likeliest misfiles.

Repos created since the last edit to tiers.json appear under Unsorted rather than being guessed at. Private repos are invisible to the API and are not counted.
